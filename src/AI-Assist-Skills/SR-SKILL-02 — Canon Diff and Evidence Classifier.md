SR-SKILL-02 — Canon Diff and Evidence Classifier

PURPOSE
Compare new Start Rail evidence against existing continuity and prevent accidental canon drift.

CORE MODEL
For every material claim, record:
Previous State → New Evidence → Classification → Resulting State → Boundary/Uncertainty.

EVIDENCE CLASSES
CONFIRMED — directly happened in played continuity.
CONFIRMED INTERPRETATION — strongly established by reliable in-world analysis, but still an interpretation.
CHARACTER BELIEF — a character believes or fears it; not objective fact.
HYPOTHESIS — explicitly proposed explanation requiring confirmation.
NPC INTERPRETATION — useful NPC conclusion that should not automatically become objective canon.
SYSTEM/UI CLAIM — status panel, generated diagnostics, relationship hearts, credits, ranks, or similar; lower authority when contradicted.
OOC CORRECTION — player explicitly corrects continuity. Highest authority for the corrected point.
NON-CANON/REJECTED — assistant draft not posted, regenerated branch the player rejected, replay artifact, or contradicted output.

AUTHORITY ORDER
1. Explicit player/OOC correction.
2. Played action/dialogue acknowledged by subsequent game response.
3. Repeated consistent narrative evidence.
4. Reliable in-world measurements/records.
5. NPC interpretation.
6. UI/status metadata.
7. Assistant draft or speculative reconstruction.

DIFF WORKFLOW
1. Load the newest relevant Drive continuity records.
2. List current state before reading the new evidence as a replacement.
3. For each candidate change, ask whether it is actually new.
4. Preserve unchanged states explicitly when new UI labels would otherwise downgrade them.
5. If sources conflict, retain both claims with evidence labels instead of averaging them.
6. Promote only when the evidence level warrants promotion.
7. Record unresolved conflict as a seam.

COMMON FAILURE MODES TO BLOCK
- Discussion of a power becomes possession of the power.
- One successful use becomes mastery/repeatability without evidence.
- NPC attraction/warmth becomes romance.
- Common mechanics become common authorship.
- A percentage display silently changes maximum capacity.
- A joke becomes formal policy.
- An imagined future becomes future canon.
- A generated relationship label downgrades a previously established stronger relationship.
- A regenerated scene becomes a second event.

CANON SAFETY EXAMPLES
Mana Sight discussed/test planned → still NOT ACQUIRED unless successfully demonstrated.
Lazuli may be a door to Bled → HYPOTHESIS.
Timothy shown as 2nd Year → OOC CORRECTION: remains 1st Year.
Dorothy authenticates into Grace → CONFIRMED voluntary transition; do not rewrite as forced overwrite.
Golden Sanctuary reduces upkeep → CONFIRMED; larger tank remains unsupported unless explicitly shown.

HARD RULE
When uncertain, preserve the uncertainty rather than forcing a clean answer.

REVISION ADDENDUM
PLAYER/OOC INTENT — player plans, possibilities, desired future direction, or contemplated actions that have not yet entered played continuity. This is distinct from OOC CORRECTION and must not be canonized merely because the player discussed it.

When evaluating the latest playable state, explicitly distinguish played edge from PLAYER/OOC INTENT.
