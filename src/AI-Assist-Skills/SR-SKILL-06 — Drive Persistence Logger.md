SR-SKILL-06 — Drive Persistence Logger

PURPOSE
Make Start Rail continuity work persistent, searchable, and verifiably written to Google Drive. When the user asks to log, persist, update continuity, or write to Drive, chat-only output is incomplete.

STANDARD RECORD FAMILIES
SR-LOG-## — chronological major/minor event continuity.
SR-REL-## — relationship deltas and standing relationship boundaries.
SR-ABILITY-## — powers, mechanics, learned theory, resources, protocols, explicit non-abilities.
SR-THREAD-## — unresolved investigations/hypotheses when enough open material warrants a dedicated record.
SR-SKILL-## — reusable Start Rail workflow specifications.

PERSISTENCE WORKFLOW
1. Search Drive first for the newest relevant record and next available number; do not create duplicates by guessing.
2. Decide whether the new material belongs in an existing record or a new numbered record based on scene/arc boundary.
3. Write the complete result, not a placeholder or chat reference.
4. Preserve user-established naming conventions.
5. Keep generator glitches/corrections visible where materially important.
6. Verify each write with Drive readback.
7. If a folder is designated, confirm the artifact is actually inside it.
8. Only then report that the material is logged.

UPDATE VS NEW FILE
Update an existing record when the user is extending the same clearly bounded arc and the record is intended to remain live.
Create a new record when a major arc boundary, new day/mission cluster, or document size/searchability makes separation useful.
Never overwrite unrelated continuity merely to keep numbering tidy.

COMPLETENESS CONTRACT
If the user asks for 'all of it,' ensure the persistent set covers:
- major events;
- minor continuity beats;
- relationship changes;
- abilities/mechanics/resources;
- agreements/protocols;
- doctrine/maxims when changed;
- unresolved and resolved threads;
- continuity corrections and do-not-promote items.

VERIFICATION CHECK
Confirm title.
Confirm content exists and is not blank/truncated.
Confirm expected major sections are present.
Confirm file location/folder when applicable.
Confirm links/IDs from actual connector result; never invent a Drive URL.

SEARCHABILITY RULES
Use stable entity names and explicit terms in prose: Timothy, Criel, Ecula, Rhea, Mana, Conceptual Energy, Golden Sanctuary, etc. Avoid overly poetic headings that hide what the document contains.

DISPATCH BEHAVIOR
/SRLog means: persist the current audit/output using this skill and verify it.
When /SRContinuity is used and the user's intent includes logging, automatically finish with this persistence workflow.

FAILURE HANDLING
If a write is blocked or partial, state exactly what did and did not persist. Do not say 'done' based on an attempted write. Retry with smaller safe batches when appropriate, then verify.

HARD RULE
'Logged' means written to Drive and read back successfully.

END SKILL
